# M5-02 / M5-03 browser and package verification

English | [简体中文](./m5-02-03.zh-CN.md)

The initial Player consumes the unchanged `@openmixture/runtime@0.1.0-alpha.0` archive. These checks complete the initial browser execution and packaged-consumer scope; three-material quality, full Player workflows and the accepted browser CI matrix remain M5-04/M5-05 work. No registry release is required.

## Browser checks

```bash
npm ci
npm run check
npm run test:browser
```

The production test build runs at `/player/`. `tests/lifecycle.spec.ts` observes real Chromium device acquisition, error scopes, mapping and cleanup through test-only platform wrappers. It imports only the installed public SDK; the normal product bundle contains no probe.

- Destroy a real device between renders and at the readback boundary. Verify structured loss, first readback failure preservation, zero tracked live allocation bytes, balanced scopes, cleanup and retained owned pixels. Explicit creation of a new device must render successfully.
- Request a misaligned map on a real staging buffer to obtain actual WebGPU validation failure. Verify cleanup, a subsequent successful render and destruction while another failed render settles.
- Load eight independent runtime modules, each with one device and four checker renders. Verify 32 clean per-call allocation reports, one cached checker pipeline per device, eight explicit destructions and retained initial output.
- Verify no uncaptured GPU errors or unhandled page failures. Count readback unmaps by buffer identity: uniform upload buffers also unmap during initialization and must not be confused with readback cleanup.
- Separately inject an unavailable API, null adapter and rejected device acquisition to test error classification. These are not successful GPU runs or evidence of spontaneous hardware failure.

The device-loss trigger is real `GPUDevice.destroy()`, with browser-delivered `device.lost` reason `destroyed`. It does not establish recovery from driver crashes, physical GPU loss or browser/tab termination. Descriptor accounting is not a measurement of physical GPU memory. The bounded checker workload does not replace M5-05 material/lifetime stress coverage.

## Isolated consumption on macOS

Commit the product changes before running this recipe. Install the locked Chromium binary first if absent:

```bash
npx playwright install chromium
node scripts/verify-isolated.mjs /absolute/path/to/OpenMixture
```

Replace the final argument with the engine checkout to deny. The script archives the clean product commit into a fresh temporary directory, excludes untracked files, and runs installation, public type checking, production build and the complete browser suite there. macOS `sandbox-exec` denies reads of both original working checkouts. A negative probe verifies that denial and that `cargo`/`rustc` are absent from the child PATH. The Node toolchain, npm dependency downloads and installed Chromium are prerequisites, not engine dependencies.

The script prints its output directory and writes `receipt.json` with the exact product commit, source archive, package/lock/fixture hashes and command results. Full command logs and the Playwright report remain temporary. Retain the necessary results and attachments in a new dated evidence record; do not overwrite the initial browser checkpoint. On other hosts run the ordinary browser recipe; this particular filesystem-denial recipe is macOS-only and does not claim a portable browser CI environment.
