## 目标与范围

用户可以打开标准 `.mix`，查看和编辑图，配置节点参数和公开绑定，撤销／重做，保存标准 `.mix`，再将保存文件交给独立 Player 和原生 CLI。契约适用时复用 Player 的运行时客户端、有界调度、通道预览和 PNG 编码。

MVP 覆盖现有节点目录与材质通道、提供键盘可操作编辑控件的桌面图工作区、选择、平移／缩放、节点移动、诊断和未保存提示。保留既有 Player 入口与流程。Studio 入口 URL 和静态 base 处理在 STUDIO-01 实施前决定，不假设当前已有新路由。

范围外：新节点或 shader 语义、3D／中间节点预览、账号、云存储、协作、工程容器、GPU 自动恢复、可嵌入 Player 分发、npm 发布和公网托管。引擎 M6 仍是独立的资源／便携打包里程碑。完成本 MVP 不依赖这些工作。

## 架构与文档规则

- 产品仅通过已安装公开包导入引擎行为。Rust 持有目录契约、验证、编译和渲染；TypeScript 持有编辑命令、文档传输和界面状态。不复制语义验证器或渲染器。
- 读取并保留输入字节，先把确切字节交给 Rust 验证，再构造可编辑视图。无效输入必须显示诊断，不得通过规范化掩盖重复键、无效 UTF-8 或数值 token。失败／迟到的导入不能替换较新工作。
- 当前公开包提供 `getNodeCatalog()`、`validate()`、`inspect()`、`createGpu()` 和 `getBuildInfo()`。检查结果暴露编译计划及公开绑定，不是无损可编辑源图；不假设已有编辑或序列化 API。
- STUDIO-01 必须解决安全的文档投影／序列化契约。产品解析器如有需要，仅用于 Rust 验证后的传输，必须保留受支持的源值和字段，避免数值精度损失。如果已安装 API 无法安全支持，先通过引擎 PR 交付由 Rust 持有的最小公开投影／序列化能力，打包，再通过独立产品 PR 验证新归档，之后开展依赖它的编辑工作。不能把编译 pass 当成源图，也不能悄然缩小可接受输入范围。
- 未编辑文档保存时保留原始字节。创作编辑可以生成新源字节；作为有效材质保存或渲染前，Rust 必须验证这些确切字节。尚不支持往返保真的情况明确保持只读，并允许下载原始字节，直到契约支持。无效草稿仍可编辑／撤销，但不能作为有效材质导出或替换当前渲染结果。
- 节点参数编辑修改创作值；Player 式请求覆盖仍为临时值。公开绑定引用标准节点／参数标识。预览覆盖不能悄然成为保存的默认值。
- 位置、视口和选择保持在 `.mix` 外。可选 `.mix.layout.json` 伴随文件由产品持有，具有版本，并关联文档身份及节点 ID。布局缺失、损坏或不匹配时使用安全默认布局，不得阻止材质验证／渲染。移动节点只改变布局的未保存状态，不改变材质字节。
- 继续限制为一个活动渲染加一个可替换的最新待处理请求。每个请求捕获源、覆盖、尺寸与通道。无效草稿、撤销／重做、源替换和关闭会使旧完成失效；这是新鲜度失效，不是 GPU 取消。过期预览不能作为当前结果导出。
- GPU 获取／释放保持显式；编辑和验证不需要 GPU。限制撤销历史及保留图像，撤销下载 URL，在导航／关闭时清理。WebGPU 缺失和设备丢失保持可见错误。

## 实施批次

### STUDIO-01——文档契约与编辑器基础

**前置条件：** 上述 M5 基线。

对照现有夹具和创作需求检查公开类型，记录字段／数值保真、编辑后序列化及不支持情况。决定入口／base 路由、模块归属、布局关联及明确的撤销历史上限。仅提取编辑器需要的 Player 共享模块。增加编辑器外壳、文件打开、原始字节验证、诊断和未保存状态处理。新增直接依赖需精确锁定并保留锁文件；本批次根据这些要求选择图界面工具。

**验收：** 棋盘格、陶瓷、皮革和木材先验证后投影；覆盖无效 UTF-8、重复键、数值边界和不支持的往返情况。未编辑保存保留确切字节。打开其他文件时处理未保存工作并拒绝迟到读取。若需要引擎 API／归档变更，须先通过生产者检查及隔离公开包消费，再关闭本批次。持续验证既有 Player 行为。

### STUDIO-02——只读图与预览

**前置条件：** STUDIO-01 及其已解决的文档契约。

使用公开目录元数据显示源节点 ID／类型、端口、连线及参数值。增加选择、平移／缩放、移动及可选伴随布局；接入现有通道预览和显式 GPU 控件。布局变更保持在源文件之外。

**验收：** 四个样例显示源图，包括合法情况下未连接的创作节点，不从优化后的渲染 pass 重建。无 WebGPU 时仍可查看图。选择和导航提供键盘控制。重置／重新加载布局不改变源字节。真实打包运行时预览匹配现有材质／通道用例；Player 在原静态 base 下仍可使用。

### STUDIO-03——图与参数编辑

**前置条件：** STUDIO-02。

基于目录增加／删除节点、连接／断开端口和修改节点参数。定义关联连线与受影响公开绑定的原子删除。将 Rust 诊断显示到相应节点／端口／参数；界面提示不替代 Rust 验证。仅从已验证的当前快照刷新预览。

**验收：** 创建棋盘格连接材质输出的图，编辑所有现有参数种类及三个材质样例。通过权威验证覆盖环、端口不兼容、端点缺失、标识重复和无效值。快速编辑保持响应且请求有界；无效草稿和旧完成不得成为当前预览／导出。真实 GPU 失败保持错误。

### STUDIO-04——撤销／重做、绑定与保存

**前置条件：** STUDIO-03。

增加有界命令历史、以一次事务记录的手势、撤销／重做、公开绑定创建／删除，以及分别保存材质／布局的操作。未保存状态分别追踪最后保存的材质和布局。源替换在处理未保存工作后建立新历史。提供丢弃草稿并回到已保存文档的方式。

**验收：** 撤销／重做恢复节点 ID、连线、值和绑定，包括节点删除，不悄然保存预览覆盖。无效草稿可修复或撤销。保存验证最终字节，重新打开恢复创作图，伴随布局失败不能改变材质语义。未编辑源逐字节下载；编辑后的源往返不丢失不受支持的字段／值。保存／新建／打开失败保留可恢复工作。

### STUDIO-05——跨消费者验收

**前置条件：** STUDIO-04。

保留 Studio 创作的棋盘格及编辑后的陶瓷／皮革／木材夹具与来源。将保存字节原样交给独立 Player 和原生 CLI 验证。产品验收只消费已安装归档；原生验证是引擎持有的独立步骤，通过分离的夹具／参考数据包交换，不使引擎检出成为产品依赖。

**验收：** 绑定产品修订、运行时归档／构建身份、源摘要、覆盖、尺寸和通道。使用适用的冻结 M5 标准比较规范化计划语义和 1K baseColor／normal／roughness／height 输出；新比较用例须在验收前固定标准，不放宽原生 golden。验证源编辑、撤销／重做、绑定、保存／重开、PNG 下载、生命周期／新鲜度失败、隔离安装及两个入口的正常静态部署。记录实际浏览器／OS／适配器／flags 和已检查截图。仅接受实测矩阵，并保留未解决限制。

## 验证与交付

每个批次执行现有产品检查：

```bash
npm run check
```

包加载、像素、输入边界、生命周期或部署变更时，执行相关真实浏览器与正常生产检查：

```bash
npx playwright install chromium
npm run test:browser
npm run test:deployment
```

扩展现有套件以覆盖该批次验收用例。文档命令、字节／值保真和历史边界使用针对性单元测试；验证／渲染／下载路径使用真实已安装运行时浏览器测试。模拟调度检查不能证明像素正确。[验收命令](./browser-qualification.zh-CN.md)记录分离材质参考包及当前 macOS 隔离步骤；声称编辑器隔离通过前需将步骤扩展到 Studio。不编造尚未实现的测试命令。

每批使用中英文配对文档、可评审提交和真实 PR。按确切修订分别记录已实现、本地验证、远端 CI 通过和已验收状态；集成前查询真实必需检查。文档计划不代表已推送远端、运行 CI 或实现验收。归档更新需记录构建身份／摘要，并重新执行公开类型／构建／浏览器及隔离消费者检查。临时输出放在忽略目录，新增带日期证据，不重写 M5 记录。

## 完成条件与独立决策

五个批次门槛全部通过，且保存的 `.mix` → 独立 Player → 原生 CLI 路径具有保留证据时，Studio MVP 完成。在最终评估中记录实测支持限制。Registry 发布、公网托管、更广浏览器／硬件验收、3D 预览和引擎 M6 分别决定范围。
