## 邀请参与者之前

产品负责人选择托管地址，并招募 **3–5 名未参与编辑器实现的外部桌面用户**。这是建议样本量，不是实际参与人数。未经授权不得发送邀请或公开参与者信息。开始前，维护者记录已验收产品提交、运行时回执、公开 HTTPS URL、部署资产摘要、部署检查及普通浏览器结果。ALPHA-03 和 registry 精确版本消费仍是发行依赖。若另行同意使用历史归档开展探索性试用，必须明确标注，且不能关闭候选验收。

使用普通桌面浏览器，不添加 unsafe-WebGPU、绕过 blocklist 或强制软件适配器参数。历史证据包含 Windows 11 build 26100、Chrome 153.0.8010.48、NVIDIA GT 1030；不能证明广泛浏览器支持或 1K 像素质量通过。记录每位参与者的实际 OS、浏览器版本和适配器。GPU 失败属于试用结果，不能算渲染成功。以 128 × 128 开始；更高分辨率可选，单独记录。

托管服务必须通过 HTTPS 提供两个生产入口和包内相对路径 WASM，并使用正确 MIME 类型。正常构建使用 `/player/`，应将 `dist/` 内容放在该前缀下。不得部署 `browser-test` 构建。其他托管前缀必须单独构建并验证。本地 `vite preview` 和受控浏览器 CI 通过都不等于外部部署。

## 参与者任务卡（约 20 分钟）

打开提供的 **Studio** 链接。先独立尝试，记录获得的帮助、困惑和失败。使用示例或非保密材质。在 GitHub 提交的反馈是公开的。产品不添加反馈遥测；只分享你选择披露的观察和文件。

| 任务 | 预期结果 |
|---|---|
| T1 · 新建 | 新建材质，找到节点控件，添加 checker 节点。 |
| T2 · 连线 | 将 checker 输出连接到材质 base-color 输入，得到有效图。 |
| T3 · 编辑与修复 | 修改 checker 参数。输入不完整／无效值，找到诊断并修复。 |
| T4 · 撤销／重做 | 撤销最近一次有效修改，再重做；说明图和数值是否符合预期。 |
| T5 · 预览／导出 | 显式初始化 WebGPU，以 128 × 128 渲染，切换通道并下载 PNG。若 GPU 初始化失败，记录诊断并继续保存。 |
| T6 · 保存 | 将材质保存为 `.mix`。可另存布局；记录浏览器将下载文件放在哪里。 |
| T7 · 独立重开 | 在新标签页打开提供的 **Player** 链接，加载刚下载的 `.mix`，初始化并渲染。对照 Studio 的所选通道，然后释放两个标签页的 GPU。在 Studio 重开 `.mix` 并检查图。 |

每项填写 **独立完成／帮助后完成／失败／未尝试**，附大致耗时和具体卡点。视觉一致性是用户反馈，不能代替原生像素门槛。若需要暴露私人材质，请停止；可只报告诊断，不上传材质。

## 反馈与观察

使用[试用反馈表](https://github.com/OpenMixture/Studio/issues/new?template=trial-feedback.yml)，模板集成至 main 后可用。参与者也可将相同字段直接交给邀请人；观察者须经许可才能转录回复。不得将 CI、Agent 会话或维护者演示计为外部参与者。

观察者分配匿名编号（P01、P02……），先记录任务结果再提供帮助，注明具体帮助内容。姓名和联系方式不进入仓库。只链接经同意的匿名证据。失败的参与者也必须记录。

| 回执字段 | 宣称完成前必需填写 |
|---|---|
| 部署 | HTTPS Studio 与 Player URL、部署时间、产品提交和资产摘要 |
| 运行时 | 精确版本、归档／registry 完整性、引擎修订、build ID 和验收链接 |
| 范围 | 探索性或已验收 Alpha；实测环境及剩余限制 |
| 参与者 | 邀请／开始／完成数量及匿名观察记录 |
| 结果 | 各任务独立完成／帮助后完成／失败／未尝试数量；分母包含所有开始者 |
| 后续 | 按优先级排列的问题，含复现、频率、严重度及证据；负责人和下一步 |

建议退出条件：至少三名外部用户尝试任务卡；至少两名独立完成从新建到保存和重开；每个阻塞都有可复现报告和负责人。这些是试用目标，不是实测成功率。若未达到，记录结果，先处理观察到的阻塞，再扩展功能。不得从截图推断反馈，也不能在收到回复之前编造优先级。

## 已同意的交付范围与命令

用户选择 GitHub Pages，并负责邀请参与者和回收反馈。本次部署定位为**历史运行时探索性试用**，不是合格 Alpha 发行。已部署根地址为 `https://openmixture.github.io/Studio/`；Studio 位于 `studio.html`，双语任务卡位于 `trial.html`。P2 证据已确认可用性及线上普通流程。手动 `Exploratory trial deployment` 工作流只允许 main，要求该精确提交的两项产品检查通过，固定历史归档，验证 `/Studio/` 生产构建，生成含产品／运行时身份和资产摘要的 `trial.json`。其他变更合并后不会自动部署。

```bash
npm run build:trial
```

本地部署检查设置 `MIXTURE_TEST_BASE=/Studio/` 后运行 `node scripts/verify-deployment.mjs`。线上普通 Windows 验证设置 `MIXTURE_ORDINARY_URL=https://openmixture.github.io/Studio/`，干净检出部署提交，再运行 `node scripts/verify-ordinary.mjs chrome /absolute/new-output`。验证器先核对部署身份及所有声明的资产摘要，再执行两个使用流程。
